## 一句话

补充证据：只在“月末最后 1 天 + 月初前 3 天”（TOM）或只在周一持有 BTC/ETH 现货，在 2023-01～2026-10 的 4 个年度样本外折里，按每边 0.30% 成本全部亏钱；建议主项目对 E-E2-turn-of-month 的 BTC/ETH 现货版本降级或加上这一条反证。

## 钱从哪里来

- 原机制（E-E2-turn-of-month）的说法是月初月末资金流（发薪、定投、调仓）集中，造成固定日历窗口的超额收益。
- 本条不提出新收益来源，只补“这个现金流在 BTC/ETH 现货上扣成本后是否还在”的样本外证据。

## 规则

- TOM：每月最后 1 个日历日和次月第 1～3 日持有单币现货，其余时间现金。
- 周一：只在周一（UTC）持有，其余时间现金。
- 日历提前已知，所以“精确日历”版本当天持有；另列出私有研究原代码的版本（原代码把窗口错后了一天：实际持有月初第 1～4 天、周二），两种都报告，避免挑好看的那个。
- 单币全仓或现金，不加杠杆。

## 证据

全部是本 bot 自己算的回测（可复现：`bots/quant/notes/xqt-migration/reproduce.py`，输出 `results.csv`，2026-10-20 运行）。4 个年度样本外折：2022-12-31～2023-12-30、2023-12-31～2024-12-29、2024-12-30～2025-12-29、2025-12-30～2026-10-13。

| 版本 | 每边 0.10%：4 折连乘 / 拼接回撤 | 每边 0.30%：4 折连乘 / 折年 / 拼接回撤 |
|---|---:|---:|
| BTC TOM（精确日历） | −26.6% / −36.0% | −39.0% / −12.2% / −45.7% |
| ETH TOM（精确日历） | −44.0% / −55.8% | −53.5% / −18.3% / −61.0% |
| BTC 周一（精确日历） | +41.5% / −23.1% | −35.9% / −11.1% / −43.9% |
| ETH 周一（精确日历） | +11.3% / −39.6% | −49.7% / −16.6% / −59.7% |
| BTC TOM（原代码，错后一天） | +16.4% / −25.3% | −3.2% / −0.8% / −30.8% |
| ETH TOM（原代码，错后一天） | −31.4% / −52.6% | −42.9% / −13.8% / −57.6% |

- 0.30% 成本下 8 个版本全部为负；0.10% 下只有 BTC 周一（精确）、ETH 周一（精确）和 BTC TOM（错后一天）为正，且都在 0.30% 下翻负——这些窗口每月或每周进出一次，换手决定了结果。
- 同期 BTC/ETH/SOL 等权持有为 +473.2%（单折最差回撤 −49.8%），日历窗口只持有 13%–14% 的天数。
- 私有研究工作台（使用者的 x-quant-trials，私有）当时对 TOM 和周一给出“拒绝”结论；本条用公开数据复现了其 ETH TOM −31.4% 的数字，并发现原代码的一天错位，已在上表分开列出。私有仓库不作出处。

## 两周内怎么检验

- 运行 `reproduce.py`；独立结果按 TOM 窗口数（约 45 个月）和周一数（约 195 周）计，均超过 30。
- 失败标准：0.30% 成本下 4 折连乘为负，或按单个窗口收益做 t 检验不显著为正，即判 BTC/ETH 现货上的 TOM/周一不值得继续。

## 成本与容量

- 每个 TOM 窗口进出各一次（每月 0.60%），周一每周进出一次（每月约 2.6%）；成本是结果翻负的主因。容量不是问题。

## 风险

- 反证只覆盖 BTC/ETH 现货、2023–2026；其他币或期货版本未测。
- 4 折样本外只有约 3.8 年；日历效应若只在特定年份出现，这里可能看不到。
