# r22 综合证据补充与独立复算

## 结论与提交建议

建议仅新增一条归因 quant-018（其上游为 quant-012）的 C52 / dot051「待核补证」，不申报新机制、不宣称策略达标或自行计分。它提供实质性的同样本比较、事件现金单位及成本边界证据，足以作为补证交评审；无需把补证本身伪装成满足全部策略门槛的新盈利策略。C19 只追加现有 dot019，保留全部旧冻结成果和失败案例。发布者仍须先读最新远端去重；这里的对手结论只针对固定版本，不声称对方当前版本仍未修正。

本轮 10 个任务围绕两个既有机制族，新增机制数为 0。独立实现从原始保留列复算，而非执行或导入对手代码；复算是算术独立，不是数据来源独立、盲测或新的前瞻试验。

## 1. quant-018：比较对象改变会改变描述结论

固定来源为仓库版本 4a7357a7f81bec8a70b4331ebfb7ba16bc5e24be，所有原成果归 quant 所有。

在完全相同的 34 个具备 start 样本的事件、23 个名义起始日期组上：

| 指标 | 均值 |
|---|---:|
| first 价格向量 Brier | 0.809283685 |
| start 价格向量 Brier | 0.743627407 |
| 原模型 Brier | 0.774672321 |

源码 brier_block 始终读取 brier_mkt_first；“at-start subset”调用仅筛选 start 可用的事件。因此原表的 market-first 标题没有算错，但该子集不能解释成 start 价格评分。换为真正 start 价格后，市场减模型从 +0.034611364 变成 −0.031044914。Brier 越小越好；这不是修复后的可交易超额收益。

预定 20,000 次配对整日期组 bootstrap 的 95% 区间：first−model [−0.056382056, 0.138501625]；start−model [−0.151207410, 0.088479889]；first−start [−0.033357663, 0.166208965]。全部含零，不证明优势、劣势、等效或独立。预先点估计已知，因此方法冻结不是盲法预注册。23 个日期组也不等于 23 个独立周。

全样本 43 事件 / 31 日期组与配对子集 34 / 23 必须分开。保留 9 个缺 start 事件与其 64 个桶，不补零，不把 242 桶当 242 个独立结果。名义七天窗口中 03-17 与 03-23 窗口会重叠，后者不能因日期标签不同就自动视为独立。

## 2. 29 份头寸只对应 11 个事件

复算 Bab 的 pure-start 规则：29 个假设单份 NO 头寸，分属 11 个有交易事件，共有 12 个 Bab 事件可用。成本 21.203、兑付 22、净额 +0.797，均为每份到期兑付 1 的单位，不是实际账户现金。21.203 已含 29 × 0.01 的 spread；规则中的另一 0.01 是入选安全余量，不可再充作已付手续费。

按份数的中位数为 +0.225，按事件中位数为 −0.115；7 个事件负、4 个正。29 份中含 18 个内部桶和 11 个外侧桶，不能把它叫作纯外侧尾部 maker 策略。固定原头寸额外每份 1c 后净额 +0.507，额外 5c 后 −0.653；额外成本盈亏平衡为 797/29000，即每份 2.748275862c。没有重新选桶、缩放资金或回填缺失报价。

实际可成交 bid/ask、深度、成交、手续费、结算/赎回/现金释放时间仍未知。不得据此推算可循环本金、年化收益或 30 个独立事件达标。

## 3. 时间可用性仍未补齐

start 是各桶在名义 UTC 零点前最后一个样本，距零点约 0.984–12.984 小时；桶之间最大差 12 小时，不是同步盘口。first 是请求范围中最早保留样本，不是独立验证的开盘首笔。

模型使用当前取得的 PortWatch 值，缺历史发布时间与 vintage。代码按 prior Monday < target start 选历史周；两个 Tuesday 开始事件在相应完整周存在时可能纳入目标区间 6 天，但原先实际历史输入列表缺失，所以这里只记录风险，不断言实际泄漏。05-25 至 06-01 可能是半开区间，未证明 off-by-one。07-13 划分是回溯划分，不是冻结的 OOS。

## 5. 复核与复现范围

role10 独立 Fraction 现金复算最大误差约 4.24e−46；重新生成全部预定抽样，264 项与最终角色输出的数值比对通过，最大浮点差 3.86e−13。24 个测试通过。测试数量不是经济贡献数量。

最小 quant018 复算只需 Python 3.12、NumPy 2.3.5 与指定提交下已有的 events.csv / buckets.csv，不复制对手数据：

    python reproduce_quant018.py --repo /path/to/pinned/repo --output result.json

脚本拒绝不匹配的 Git blob，接受普通 Git 字节或本次已记录的额外一个 LF 导出。去掉一字节只在内存里校验，不改原文件。结果与 REPLICATION.json 的 p1 完全一致。

C19 完整独立复算还需 INPUT-HASHES.json 指定的原始保留资金费、价格与预热输入；这些不在本次最小发布包内。不得声称只靠聚合结果就能重建所有历史现金、保证金或相关性。replicate.py 可对齐已保留输入运行，但本地默认路径不等于公开可取得的输入。发布小型聚合是审阅材料，不替代完整数据取得说明。
