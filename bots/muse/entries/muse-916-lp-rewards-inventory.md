## 一句话

还是在 Polymarket 奖励市场挂单领奖励（与 M-M4-poly-rewards 同一个付款方：平台流动性奖励预算；**不是 muse-800/915 的吃单费返佣**），但把「挂上就完事」改成一套净现金流决策：逐市场算奖励份额与逆向选择成本，只做净值为正的市场和时段；库存用完整集 merge 平掉而不是扛方向；两边报价按 Q-score 的「取小」规则自动回拉失衡的一侧；计划内事件和毒性窗口主动撤单。

## 与 muse-800 / muse-915 的收益边界（非拆条）

- **800**：赚 `R_800 = R_maker(crypto 20%) + 价差`，库存靠完整集铸造；不依赖已结束的 crypto TWAP 奖励池。
- **915**：赚 `R_915 = R_maker(长日期事件板块，实际筛选 rebateRate ≥20%) + 价差`，无完整集；它是 800 返佣组件的 supplement（`improves: muse-800`）。
- **916（本条）**：赚 `W = Q_final × pool_m + 价差`，`Q_final` 由官方 Q-score 归一化得到；付款方是平台奖励预算，不是吃单费。奖励市场若同时有吃单费，`R` 可能存在，但必须把 `R` 与 `W` **分账**，不能把同一笔成交的 rebate 和 reward 加两次。
- **结论**：916 不是 800 的子集或换参数，不需要降为 supplement；它是对 M-M4/dot-032 的 improvement，与 800/915 的边界是「奖励池 vs 吃单费返佣」。

## 钱从哪里来

与原版相同：Polymarket 的流动性奖励预算，不是吃单费返佣。平台按官方 Q-score 给「离中间价近、尺寸够、双边」的挂单计分，按 UTC 日把每个市场的奖励池按 `Q_final` 份额分给 maker，最低支付 $1（官方 `docs.polymarket.com/programs/liquidity-rewards` 原文，2026-10-21 已读；dot-032 仅作内部整理稿交叉核对）。平台用奖励换深度和紧价差，预算在就会付。**改进的不是付款方，是把名义奖励变成净正现金流的方法**：奖励是毛收入，逆向选择和资金占用是成本，原版没有成本侧的规则，所以很容易出现「领到 $30 奖励、库存亏 $50」的假赚钱。

## 规则

- **先筛池子（防领已结束的奖励）**：每天用 Gamma 拉 `clobRewards` 非空的市场清单，逐市场读 `rewardsMinSize`（最低合格股数）、`rewardsMaxSpread`（离中间价的最大计分距离，单位美分）和日池金额；**crypto 5 分钟/15 分钟/4 小时 TWAP 奖励已于 2026-08 结束**（官方文档原文：“This program has ended. The August allocation is no longer active.”，2026-10-21 已读），这类市场即使 Gamma 还挂着旧字段也不做，除非当日奖励到账样本能证明池子还活着。
- **净值决策（逐市场、逐日）**：预估日奖励 = 日池 × Q_own/(Q_own + Q_others)，其中 Q_others 按当前 CLOB 簿上 rewardsMaxSpread 内的挂单量用官方公式 `S(v,s)=((v−s)/v)²·b` 粗算；预估成本 = 近 3 日该市场成交 markout（成交后 30 分钟中间价漂移）中位数 × 预期日成交股数。**净值 ≤ 0 的市场不挂**。这是原版没有的进门规则。
- **报价与双边回拉**：双边买单，起始价 = 调整后中间价 ∓ 1¢，尺寸 = max(rewardsMinSize, 50 股)。Q-score 在中间价位于 [0.10, 0.90] 时取两侧的 `Q_min`（单边按 c=3.0 折损），所以一边成交后失衡会浪费另一边的分：成交后立即把重的一侧报价外移 1¢、轻的一侧内移贴回中间价，把 Q 拉回平衡；这一步是原版固定报价没有的。
- **库存去化（merge，不扛方向）**：任一市场净库存 |YES−NO| > 100 股，或两边库存都 ≥ 50 股时，用完整集 merge（1 YES + 1 NO → $1）把可配对部分平掉，merge 后继续挂单；merge 不产生方向损益（gas 经 relayer，本条目未实测 gas 成本，标未验证）。原版只有「每侧 ≤ 50 股」的上限，没有去化路径，撞上限就只能停挂或裸扛到结算。
- **毒性门（逆向选择规避）**：以下窗口撤单或尺寸减半：(1) 计划内信息事件（民调/宏观数据/官方日程）公布前 30 分钟到公布后 15 分钟；(2) 中间价 15 分钟内移动 > 3¢；(3) 中间价跌出 [0.10, 0.90]（此区间外计分要求严格双边且结算风险陡增）；(4) 该市场前一日 markout 中位 > 2¢ 时，次日只挂 rewardsMaxSpread 的外半区（牺牲分数换安全）。
- **退出**：结算前 48 小时停止挂单并 merge/平仓清零库存；奖励按日到账，未满 $1 的零头不计入收益预期。
- **结算规则要点**：目标为长日期事件市场，结算源按各自 Gamma 规则原文（官方结果、主流媒体共识或官方统计）；本策略在结算前退出，结算规则只决定退出时点与毒性窗口，不构成收益来源。

## 证据

- **官方（2026-10-21 已读）**：`docs.polymarket.com/programs/liquidity-rewards` 原文给出 `S(v,s)=((v−s)/v)²·b`、`c=3.0`、`Q_min` 在 [0.10,0.90] 内取 `max(min(Q_one,Q_two), max(Q_one/c,Q_two/c))`、区间外须双边、epoch = 一个 UTC 日、订单簿每分钟随机偏移采样一次（最多 1,440 样本）、`Q_final` 归一化、奖励按日午夜 UTC 发放、最低支付 $1；`rewardsMinSize`/`rewardsMaxSpread`/`clobRewards` 字段见官方 market-details 页。dot-032 仅作内部整理稿交叉核对（二手），不再作为核心公式的唯一出处。
- crypto 5m/15m/4h TWAP 奖励「This program has ended」：官方 liquidity-rewards 页原文，2026-10-21 已读。**是否还有其他已结束/新开的池子，未逐一核实**，靠规则里的 Gamma 实时筛选兜底。
- 奖励量级：Turbine（**二手/厂商博客**，已读）称流动性奖励逐分钟给订单计分、按日午夜 UTC 发放、双边权重高于单边，记录在案的单市场奖励上限可达 $52,000（2026 世界杯决赛，来源自报，未核实）——说明头部池子足够大，但长尾小池的份额竞争才是常态，这也是要做 Q 密度筛选的原因。**不能把 Turbine 当官方。**
- 库存风险与「结算前展平」：Turbine（**二手/厂商博客**，已读）系统讲了二元合约做市的 inventory/ gap / pin 风险与 flatten-before-resolution 原则，支持本条目的 merge 去化与提前退出设计（方法论引用，非收益证据）。
- 原版做法对照：dot-032 的纸面方案是「双 bid、各自 adjusted mid −1¢、每侧最多 50 份」固定参数；本条目的净值决策、双边回拉、merge 去化、毒性门都是在它和 M-M4 名称机制之上的增量。

## 两周内怎么检验

前向 14 天并行跑两个纸面版本：**基线** = dot-032 式固定 50 股双边；**本版** = 净值决策 + 双边回拉 + merge 去化 + 毒性门的完整规则。对 ≥30 个有池市场（同一事件的多档合并为 1 个事件簇）逐日记录：估算 Q 份额、当日池子、纸面成交（队列假设：只计排在纸面单之前的深度被吃掉后的成交）、成交 markout、merge 次数、奖励按份额模型结算。比较两版的「净现金流 = 奖励 − markout 损失」中位数与净正天数占比。失败标准：本版净现金流中位 ≤ 0（策略本身不成立），或本版相对基线的净值差中位 ≤ 0（改进不成立）——两条任一触发即判失败，结论如实写回条目。

**R/W 分列表（915 不进入 916 的检验样本，只共用成交台账并分别标 R/W；W 与 R 不相加、不双计）：**

| 账目 | 样本 | 收入 | markout | 失败线 |
|---|---|---|---|---|
| **W（916 奖励池，入检验）** | ≥30 个有池事件簇，前向 14 天 | `W = Q_final × pool_m`（按官方 Q-score 份额；以自有钱包公开 activity 对账） | 只计 W 持仓成交后 30 分钟中间价漂移 | 净现金流（W − markout − 资金占用代理）中位 ≤ 0，或相对基线净值差中位 ≤ 0 |
| **R（915 返佣，仅对照/另账）** | 同一成交台账中实际产生 rebate 的成交；不计入 W 的 ≥30 事件簇分母 | `R = rebateRate × 吃单费份额`（按 maker-rebates 公式，另账） | 与 W 同源成交的 markout 只记一次，不重复计入 W | R 只作对照；R 的正负不改变 W 的成败判定，也不与 W 相加 |

## 成本与容量

- 成本：maker 手续费 0；成本主体是 markout（逆向选择）和资金占用——奖励市场多为长日期，50 股 × 双边 × 均价 0.5 ≈ $50/市场的挂单资金，但库存累积后实际占用可达数百美元/市场。按单场所 ≤ 2,500 USDT、总资金 5,000 USDT，可同时做 5–8 个中等池市场。
- 粗算（量级，未实测）：日池 $200 的市场，若占 Q 份额 10%，日奖励 $20；同市场日成交 100 股、markout 中位 1¢，成本 $1——净值为正的关键不在奖励大小，而在避开 markout 5¢ 以上的毒性日（一次坏日的成本可吃掉一周奖励）。这正是净值决策与毒性门要证明的东西。
- 频率：奖励按日结算，天天有结果；每月可选池随平台上新变化，需每日重筛。

## 风险

- **规则/政策风险**：Q-score 公式、c 值、池子金额全由平台单方设定且可随时改（已有整类项目结束的先例）；公式一改，本条目的回拉与筛选参数要重估。
- **份额稀释**：池子固定时其他 maker 涌入会摊薄 Q 份额，净值决策按日重算只能跟随、不能阻止。
- **纸面成交假设风险**：检验靠队列假设估成交，真实排队位置拿不到（无历史 L2），纸面 markout 可能低估毒性——失败标准已按中位数从严。
- **merge 执行**：merge 需链上操作（或 relayer），研究阶段不执行；gas 与 relayer 可用性未实测，若 merge 成本高于预期，去化环节要改成互补侧吃单平仓（多付半个价差+吃单费）。
- **与返佣的口径重叠**：奖励市场若同时有吃单费，挂单成交还会产生返佣（muse-915，已收敛为 muse-800 的 supplement），检验必须把 `W`（奖励池）与 `R`（吃单费返佣）分开记账，避免同一笔收入双计。

## 改进了什么

对 known/M-M4-poly-rewards（主项目已有机制：预测市场挂单领奖励）与 dot-032（同机制的完整规则整理稿）的改进，共五点：
1. **从「挂单」到「净值决策」**：原版只描述计分与资格，没有「这个市场值不值得挂」的进门规则；本版逐市场逐日估算奖励份额减 markout 成本，净值 ≤ 0 不挂——把奖励从毛收入变成净现金流目标。
2. **双边回拉**：利用 Q_min 取两侧最小值、单边 c=3.0 折损的结构，成交失衡后自动调整两侧报价距离恢复计分效率；原版固定 mid−1¢ 不回拉，失衡时白白丢分。
3. **merge 去库存**：原版只有仓位上限、没有去化路径；本版用完整集 merge 把库存打回现金，可无限续挂而不累积方向风险。
4. **毒性门**：原版无逆向选择规则；本版对计划内事件、急动、跌出计分区间、高 markout 日四种情形给出撤单/减半/外移的明确动作。
5. **池子存活筛选**：原版未处理「奖励项目已结束」的状态（crypto TWAP 奖励 2026-08 已结束）；本版以 Gamma clobRewards 实时非空为进门条件。
怎么验证改进：两周检验与基线（原版固定参数）纸面并行对比，净现金流中位差 ≤ 0 即判改进不成立（见检验节）。

## 撞车与边界

与上游 C49（再质押安全服务费与罚没风险）不同：C49 做外部 AVS 安全服务费与罚没风险，本条赚 Polymarket 流动性奖励池，不涉及质押、AVS 或罚没；与 C33（预测市场持有奖励净收益）不同：C33 做持有头寸奖励，本条按 Q-score 双边挂单领奖励池，付款科目与动作不同。与 C32（平台流动性激励）同族：本条按 dot-032/M-M4 计 improvement，不另计新机制；本条不改为 new，也不主张与 C49/C33/C32 的边界已由工具正式通过。

## 门槛自查

1. 机制说得清：满足。付款方与原版同为平台流动性奖励预算（为深度与紧价差付费）；改进点说得清：用净值决策、回拉、merge、毒性门把毛奖励变成净现金流。
2. 有免费数据能检验：部分满足。池子参数、成交、当前盘口都免费免密钥；历史 L2 缺失，Q 密度与 markout 只能从 2026-10-20 起前向记录，已按 GUIDE 预测市场口径写明起点；独立结果按事件簇计，前向 14 天可达 30+。
3. 小资金能做：满足。单场所占用 ≤ 2,500 USDT，总 5,000 可跑 5–8 个市场；不杠杆，卖单须有库存，库存靠 merge 去化不裸扛。
4. 不重复：满足（以 improvement 形式）。与 M-M4 是改进关系而非变体：关键增量在成本侧与库存侧（净值决策、merge 去化、毒性门、双边回拉），且检验设计了与原版基线的对照与失败标准；与同批返佣条目（muse-915，已收敛为 muse-800 的 supplement）付款机制不同（预算池 vs 吃单费分成）；与 muse-800（5 分钟完整集铸造做市）区别：它靠铸造完整集在 300 秒窗口内卖双边，本条目在长日期奖励市场挂单、merge 只用于去库存。**916 不是 800 的子集或换参数**，保留 improvement，不拆成独立 new。
5. 扣成本后粗算够用：不确定。这正是本条目要检验的命题：毛奖励量级可算（池子×份额），但扣 markout 后是否净正、是否优于基线，无公开历史数据可回算，只能前向两周见分晓，不硬编结论。
6. 两周内能检验：满足。前向 14 天、≥30 个事件簇、与基线对照、双重失败标准（净值中位 ≤ 0 或相对基线无改善）均已写明。
7. 出处可查：满足（核心规则已由官方原文逐条补核）。官方 `docs.polymarket.com/programs/liquidity-rewards`（2026-10-21 已读）给出 S(v,s)=((v−s)/v)²·b、c=3.0、[0.10,0.90] 内 Q_min 取 min 与单边/c 的较大值、区间外须双边、每分钟随机采样（最多 1,440 样本）、UTC 日 epoch、按日午夜 UTC 发放、**最低支付 $1**；官方 `market-data/market-details` 给出 `rewardsMinSize`/`rewardsMaxSpread`/`clobRewards` 字段；官方 `programs/maker-rebates` 给出返佣公式，用于与本条目分账。dot-032 只作内部整理稿（二手），Turbine 只作厂商博客（二手），均不冒充官方；Turbine 的 $52,000 池上限仍标来源自报、未核实。
